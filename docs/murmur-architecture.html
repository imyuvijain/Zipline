Proposal for review

Murmur: what your team is doing, seconds old

Every laptop runs a small local scout. It watches cheaply and all the time, keeps the raw activity on the laptop, and only spends model tokens when someone asks or when two people collide. Below: the whole system, every step of each flow, and what the person sees at each step.

answers ≈ 5–12 s old 0 tokens when nobody asks raw activity never leaves the laptop DeLM board: append-only, claims, no coordinator

02 · Every step

The five flows

Claims and heartbeats run all the time and use no model. The local model wakes only for an ask or a trigger. Claude runs only to compose an answer or a rollup.

A · Always on

0 tokens
  1. LaptopCollectors read the frontmost window, git state and file saves.
    every 10 s
  2. LaptopPrivacy filter drops non-work apps and redacts secrets.
    <1 ms
  3. LaptopEvents go into a 30-minute rolling buffer. Older events are deleted.
    local
  4. Laptop → Board① If the work area changed (new branch, new folder, new doc), publish a claim.
    ≈1 s
  5. Laptop → BoardHeartbeat marks the person active, idle or offline. Offline claims expire after 10 min.
    every 15 s

B · Someone asks

≈5–12 s · data seconds old
  1. Voice / chat② "What's Priya doing?" or "What's the team on?"
    0 s
  2. Board · AlterCheck the asker may ask about this team. Log the read.
    <0.2 s
  3. BoardCache under 3 min old? Answer straight away and skip to step 7.
    instant
  4. Board → Laptops③ Router picks whose laptops to ask from claims and sends the question to each, in parallel.
    <0.5 s
  5. Laptop④ Local model summarizes the buffer around the question. Max 300 chars, with file and commit refs.
    3–8 s
  6. LaptopThe person who was asked about sees "Sam asked · sent 1 summary" in their tray.
    same time
  7. Board · Claude⑦ Compose the answer. Counts come from SQL, prose from Claude. Every claim cites a source and its age.
    1–2 s
  8. Voice / chatElevenLabs speaks it, or chat shows it with source chips.
    streams

C · Collision

fires within ≈1 min
  1. BoardA new claim arrives (flow A, step 4).
    0 s
  2. BoardDetector checks for overlapping areas (path or doc), then the same task in different files (embedding match plus a quick model check).
    <2 s
  3. Board → Laptop⑤ Match found. Alert the second person only. The first keeps working.
    ≈1 s
  4. Laptop · ElevenLabsSpoken line plus a notification with Ping, Pair or Different thing.
    ≈1 s
  5. Board"Different thing" mutes that pair for an hour and teaches the detector.
    —

D · Repeated dead end

one small model call
  1. LaptopTrigger: a test or build failed, a revert, or 10 min in one area with no commit.
    event
  2. LaptopLocal model writes a short FAIL: what was tried, what happened.
    3–5 s
  3. Laptop → Board⑥ Publish it. It stays open until someone resolves it.
    ≈1 s
  4. Board → LaptopA teammate later claims the same area and hits the same error. Echo: "Sam tried that 20 min ago."
    on match

E · Department or company

built from cached answers
  1. Voice / chat"What's engineering blocked on?"
    0 s
  2. Board · AlterDept and company scopes get digests only, never one person's activity.
    <0.2 s
  3. BoardReuse team answers under 3 min old. For stale teams, run flow B.
    0–10 s
  4. Board · RowboatPull the relevant procedure from company memory ("deploys need 2 reviews").
    <1 s
  5. Board · ClaudeMerge into one answer. Blocked counts come from SQL. Shows the age of the oldest input.
    1–3 s

05 · Before the build

Decisions to approve or change

  1. Pull answers, push only claims and failuresThe local model runs only when asked or triggered. Claims and heartbeats run all the time and use no model.
  2. Inputs: window title, git, file savesNo screenshots, no Slack, no email. Enough to prove liveness in the demo.
  3. Collision alerts go to the second person onlyThe first person is never interrupted. Ping, Pair or Different thing.
  4. Everyone sees who asked about themAlter audit log in the tray, plus pause and delete. Dept and company get digests only.
  5. One real team, simulated other teamsA seed script, labeled "sim" on screen. Expected Parrot is used for the validation survey, not the fake data.
  6. Web stack: Wasp or Vite + ReactWasp only if someone has shipped with it. Otherwise Vite, with assistant-ui either way.
